# 검색엔진 본문 수집 및 뉴스 후처리 개선

- Created at: 2026-07-02 19:01:05

## Purpose

Google RSS, Naver News API, Daum/Kakao Web Search 기반 수집 결과에도 실제 기사 본문을 저장하고, 저장된 본문을 SQLite 뉴스 UI API와 감성 판단 흐름에서 활용할 수 있게 한다.

또한 오케스트레이션 화면의 스케줄 상태 조회와 cron/lock 처리를 보완해 수집 테스트 중 페이지가 느려지거나 잘못된 스케줄 값이 저장되는 문제를 줄인다.

## Why This Change Was Needed

- 검색엔진 3종은 기존에 제목/요약 중심 데이터만 안정적으로 저장했고, 실제 기사 본문은 일반 언론사 XPath 수집 결과보다 부족했다.
- 개발팀 요청에 따라 Google/Naver/Daum 수집 결과도 `items/*.json`, SQLite, API 후처리에서 본문을 사용할 수 있어야 했다.
- 감성 판단은 제목만 보면 기사 맥락을 놓칠 수 있어, 본문까지 포함한 판단 입력이 필요했다.
- Google News RSS는 `news.google.com/rss/articles/...` 중계 URL을 내려주므로 원문 URL 디코딩 없이는 본문 추출 성공률이 낮았다.
- 오케스트레이션 화면은 scheduler registry가 비어 있어도 Windows Task Scheduler 상세 조회를 시도해 불필요하게 느려지는 경우가 있었다.

## What Changed

### 본문 추출 공통 모듈

- `crawler_app/article_body_extractor.py` 추가.
- `newspaper3k` 기반 본문 추출 wrapper를 제공한다.
- 공통 결과 필드:
  - `body`
  - `body_url`
  - `body_extract_status`
  - `body_extract_error`
  - `body_char_count`
  - `body_extractor`
- `SEARCH_NEWS_BODY_TIMEOUT_SECONDS` 기본값은 7초.
- `SEARCH_NEWS_BODY_MAX_WORKERS` 기본값은 3.
- `SEARCH_NEWS_BODY_EXTRACT`로 본문 추출을 끌 수 있다.

### Google RSS 본문 수집

- `crawler_app/google_news_rss.py`에서 저장 대상 item에 본문 추출 필드를 병합한다.
- Google News 중계 URL을 `googlenewsdecoder`로 원문 URL로 해석한 뒤 `newspaper3k`를 실행한다.
- `GOOGLE_NEWS_DECODE_TIMEOUT_SECONDS` 기본값은 6초.
- `GOOGLE_NEWS_DECODER=0/false/no/off`로 decoder를 끌 수 있다.
- 디코딩 실패 시 수집 전체를 실패시키지 않고 item별 `body_extract_status=failed`로 남긴다.

### Naver/Daum 본문 수집

- `crawler_app/naver_news_api.py`에서 `originallink` 우선, 없으면 link/detail URL 기준으로 본문을 추출한다.
- `crawler_app/daum_news_api.py`에서 Daum 기사 상세 URL 기준으로 본문을 추출한다.
- Daum은 상세 URL 접근으로 source/domain 보강을 수행하는 기존 흐름과 본문 추출을 함께 사용한다.

### SQLite 뉴스 UI 후처리

- `crawler_app/news_ingestion.py`에서 `workflow_records.json`에 본문이 없으면 연결된 item JSON에서 본문 필드를 읽어 SQLite에 저장한다.
- `crawl_articles`에 `body`, `body_extract_status`, `body_url` 계열 컬럼을 migration으로 추가한다.
- `crawler_app/news_sentiment.py`에서 감성 판단 입력을 `title` 중심에서 `title + body` 기준으로 확장했다.
- `crawler_app/news_sqlite_store.py`에는 pull로 받은 최신 API 변경과 로컬 본문/카테고리 관련 변경이 함께 반영되어 있다.

### Workflow/설정 연동

- `crawler_app/workflow.py`에서 parser item snapshot이 본문 관련 필드를 보존하도록 보완했다.
- `configs/구글.json`, `configs/네이버뉴스.json`, `configs/다음.json`은 검색엔진 3종 테스트와 category/filter 설정 변경을 반영한다.

### 오케스트레이션 보완

- `crawler_app/orchestration.py`
  - cron 다음 실행 계산을 KST 기준으로 보정했다.
  - lock 파일의 PID가 실제 살아 있는지 확인하는 stale lock 보강을 추가했다.
  - runtime state에 cron을 함께 저장해 잘못된 next_run_at 덮어쓰기를 줄였다.
- `crawler_app/web.py`
  - 잘못된 cron 값은 저장되지 않도록 검증한다.
  - scheduler registry가 비어 있으면 Windows Task Scheduler 상세 조회를 건너뛰어 오케스트레이션 페이지 상태 조회 지연을 줄였다.

### 문서/리포트

- `docs/reports/search_engine_body_collection_summary.html` 추가.
- 개발팀 전달용으로 검색엔진 3종의 수집 기사 수, 본문 성공 수, 300자 이상 본문 확보 수, 미확보 원인을 시각화했다.
- 핵심 지표는 단순 본문 성공률이 아니라 300자 이상 본문 확보율이다.

### 의존성

- `requirements.txt`에 `newspaper3k` 및 관련 본문 추출 의존성을 추가했다.

## Design Judgment

- 검색엔진 3종 외 일반 XPath 크롤러의 본문 추출 방식은 건드리지 않았다.
- 본문 추출 실패는 수집 실패로 전파하지 않고 item 단위 실패 상태로 남겼다.
- Google은 품질 확보를 위해 decoder timeout 6초, body timeout 7초, workers 3을 기본값으로 유지한다.
- 1차 시나리오 테스트 결과, 단순 timeout 단축 또는 worker 상향은 Google URL 디코딩 안정성을 크게 깨뜨렸다.

## Alternatives Considered Or Deferred

- Google URL 디코딩 캐시와 본문 캐시는 반복 테스트나 운영 누적에는 효과가 있으나, 매번 데이터를 비우고 새로 수집하는 테스트에서는 우선순위가 낮아 이번 push 범위에서 제외했다.
- Google fallback으로 trafilatura/readability/site-specific extractor를 붙이는 방안은 품질을 올릴 수 있지만 실행 시간이 늘 수 있어 보류했다.
- Google 전용 구조 개선안으로, URL 디코딩 단계와 newspaper 본문 추출 단계를 분리하는 설계를 다음 후보로 남겼다.

## Validation

- `python -m compileall crawler_app`
- `python -m unittest tests.test_news_ui_api -v`
- Google/Naver/Daum limit 20 수동 실행 및 SQLite 반영 확인.
- 최종 통합 수집 결과:
  - Google: 353건, 본문 성공 330건, 300자 이상 294건, 300자 이상 비율 83.3%
  - Naver: 939건, 본문 성공 893건, 300자 이상 836건, 300자 이상 비율 89.0%
  - Daum: 737건, 본문 성공 736건, 300자 이상 734건, 300자 이상 비율 99.6%
- Google limit 5 시나리오 9개를 실행해 기본값 유지 판단:
  - G01 baseline: 300자 이상 81.3%, 9.26분
  - G04 body timeout 5초: 300자 이상 81.7%, 9.43분
  - decode timeout 4초/3초, body timeout 4초, workers 4/5, 조합형은 Google URL 디코딩 실패가 커서 탈락.

## Remaining Risks

- Google은 원문 사이트 구조, 외국 언론/투자 사이트, 403 차단, timeout에 따라 본문 미확보가 발생한다.
- 300자 미만 저품질 본문은 body 추출 성공으로 기록될 수 있으므로 운영 지표에서는 `body_char_count >= 300`을 함께 봐야 한다.
- 현재 마지막 시나리오 테스트 결과가 로컬 outputs/SQLite에 남아 있을 수 있으므로 운영 테스트 전 초기화가 필요하다.
- Google 속도 개선은 단순 환경변수 조정이 아니라 디코딩/본문 추출 단계 분리 구조 변경이 필요하다.

## Cumulative Prompt / Request Flow

- 개발팀 요청으로 Google/Naver/Daum 검색엔진 3종에도 본문 수집을 추가하기로 했다.
- 사용자는 본문 저장 자체보다 실제 활용 가능한 300자 이상 본문 확보율을 개발팀에 보고해야 한다고 요청했다.

- 속도 개선을 위해 decode timeout/body timeout/workers 1차 9개 시나리오를 테스트했으나, baseline 유지가 가장 안정적이라는 결론을 냈다.
