# CR GR 설정 수집 최대치 제한 해제

- Created at: 2026-07-01 18:11:33
- Branch: dev/API+Tran

## Purpose

CR/GR 카테고리 크롤러 설정에서 실행 단계 `open_detail`의 수집 최대치 제한을 해제한다.

## Why This Change Was Needed

CR/GR 항목은 설정된 페이지 범위 안에서 노출되는 상세 항목을 제한 없이 수집해야 하므로, 일부 설정에 남아 있던 `loop_limit` 값이 수집 누락을 만들 수 있었다.

## What Changed

`category`가 `CR` 또는 `GR`인 설정 12개에서 `steps[0].loop_limit` 값을 제거했다. UI 기준으로는 실행 단계 `open_detail`의 limit 칸을 비운 변경이다.

## Design Judgment

소스코드는 변경하지 않고 설정값만 수정했다. 요청 범위가 실행 단계 최대치 해제였고, 기존 크롤러 실행 로직은 limit 값이 없으면 기존 반복 조건에 따라 수집할 수 있기 때문이다.

## Alternatives Considered Or Deferred

모든 설정의 limit을 일괄 제거하는 방식은 제외했다. 이번 요청 범위는 CR/GR 카테고리 항목으로 제한되어 있었다.

## Validation

`category=CR/GR` 설정 전체를 재검사해 `loop_limit`, `item_limit`, `limit` 키가 남아 있지 않음을 확인했다. `git diff --check`도 통과했다.

## Remaining Risks

limit 해제로 각 사이트의 페이지/목록 구조에 따라 수집 건수가 늘어날 수 있다. 이는 요청된 동작이며, 실행 시간 증가는 실제 수동 실행으로 확인해야 한다.

## Cumulative Prompt / Request Flow

사용자가 GR/CR 카테고리 항목 중 실행 단계 `open_detail`의 limit 칸에 남아 있는 숫자를 제거해 달라고 요청했다. 실제 JSON 필드는 `loop_limit`이었으므로 해당 필드만 제거했다.
