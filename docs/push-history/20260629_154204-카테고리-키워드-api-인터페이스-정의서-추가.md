# 카테고리 키워드 API 인터페이스 정의서 추가

- Created at: 2026-06-29 15:42:04
- Branch: dev/API+Tran

## Purpose

개발팀 전달용으로 최근 추가/변경된 카테고리 키워드 관리 API와 카테고리 기반 뉴스 조회 확장 파라미터의 인터페이스 정의서를 repo 최상위에 추가한다.

## Why This Change Was Needed

개발팀에서 UI 연동을 위해 어떤 API가 추가되었고, 어느 파일에 위치하며, 어떻게 호출해야 하는지 확인할 수 있는 인터페이스 정의서를 요청했다. 기존 전체 API 설명이 아니라 최근 개발 범위만 빠르게 확인할 수 있도록 문서 범위를 축소했다.

## What Changed

- `news-ui-api-interface-definition.md`를 repo 최상위에 추가했다.
- 문서에는 카테고리 키워드 관리 API 그룹과 기존 `/api/news`, `/api/news/grouped`, `/api/stats`의 `category_code`, `keyword_group` 파라미터 확장만 정리했다.
- 로컬 PC 절대경로는 문서에서 제외하고 repo-relative 파일명만 남겼다.

## Design Judgment

개발팀 전달 문서이므로 로컬 환경 경로, 기존 전체 API, SQLite 내부 상세 전체 설명은 제외했다. 대신 UI 연동에 필요한 endpoint, method, request/response 예시, DB 변경 테이블, UI 적용 방식을 중심으로 구성했다.

## Alternatives Considered Or Deferred

- 전체 뉴스 리뷰 API 정의서 형태는 범위가 과해 제외했다.
- 기존 read/favorite/analysis API 상세 설명은 이번 신규 요청의 핵심이 아니므로 본문에서 제외했다.
- 문서를 `docs/` 아래에 둘 수도 있었지만 사용자가 "경로 최외곽"을 요청했으므로 repo 최상위에 배치했다.

## Validation

- `git diff --check` 실행: 공백 오류 없음.
- 문서 내 로컬 절대경로/개인 PC 경로/`127.0.0.1` 문자열 검색: 발견 없음.
- `git status --short`로 변경 파일 범위 확인.

## Remaining Risks

이 문서는 인터페이스 정의서만 추가하며 런타임 코드는 변경하지 않는다. 실제 UI 연동 중 request/response shape 추가 요청이 생기면 문서를 별도로 보완해야 한다.

## Cumulative Prompt / Request Flow

사용자는 처음에 전체 API 문서가 너무 넓고 로컬 경로가 포함되어 부적절하다고 지적했다. 이에 따라 최근 요청 범위인 카테고리 키워드 관리 API와 카테고리 기반 조회 확장만 남긴 축소 정의서로 다시 작성했다. 이후 사용자는 해당 파일을 repo 최상위에 빠르게 push하라고 요청했다.
