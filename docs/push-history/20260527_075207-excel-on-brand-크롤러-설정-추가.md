# Excel ON Brand 크롤러 설정 추가

- Created at: 2026-05-27 07:52:07
- Branch: dev/crawler-current

## Purpose

Excel workbook `ON` and `Brand` monitoring targets were converted into crawler workflow config files so the orchestration page can run keyword-filtered monitoring jobs for those sites.

## Why This Change Was Needed

The operator asked to create crawler settings from the supplied monitoring-site workbook without changing source code. The key product constraint is that `search_terms` are URL/page parameters in this crawler, so the Excel keywords must not be written there. They need to be saved as `filter_terms` so collected page records are filtered after fetching.

## What Changed

- Added 29 `configs/excel_on_*.json` workflow configs from the Excel `ON` sheet.
- Added 7 `configs/excel_brand_*.json` workflow configs from the Excel `Brand` sheet.
- Added this push-history record.
- No Python, frontend, scheduler, template, test, or runtime source file was changed.

## Design Judgment

The generated configs keep `search_terms: []` and place workbook keywords into `filter_terms`. For each site, a monitoring URL was selected from a legal/news/press/publication/notice-style page when discoverable. Where two stable repeated item links could be inferred, the config uses validator-compatible `xpath` and `xpath_2` pairs. Where a repeated pair could not be safely inferred, the config falls back to a single selected link or page-body filtering and records the limitation in `notes`.

## Alternatives Considered Or Deferred

- Do not place keywords into `search_terms`: deferred intentionally because this would alter URL parameters and violate the operator instruction.
- Do not edit crawler source to support site-specific parsers in this slice: deferred because the user explicitly requested no source-code change.
- Do not enable/start monitoring in this commit: deferred because this commit only publishes settings; live scheduler mutation and output observation should remain a separate operational step.

- Facebook returned 400; YouTube, Instagram, Facebook, and X may require login, JavaScript-heavy flows, channel-specific URLs, or official APIs for reliable monitoring.
- Some absolute XPath values may need browser DevTools verification if the site changes its DOM.

기존 소스코드 변경 없이 설정만으로 가능한 사이트는 설정값을 맞추고, 설정만으로 안정 수집이 어려운 사이트는 notes에 제한사항을 기록했다. 이 구분은 이후 개발자가 "설정 보정으로 해결할 사이트"와 "공통 workflow 또는 parser 보완이 필요한 사이트"를 빠르게 나누어 판단할 수 있게 하기 위한 것이다.

### Design Notes And Tradeoffs

- `search_terms`는 기존 제품 계약대로 검색 키워드가 아니라 URL/page 파라미터로 사용한다.
- Excel 또는 사용자 지정 키워드는 가능하면 `filter_terms`에 유지한다.
- 설정만으로 반복 수집이 가능한 사이트는 `xpath` / `xpath_2`를 크롤러 loop 일반화 방식에 맞춰 조정했다.
- ISO, S-OIL, kormany.hu처럼 JSON/API 또는 SPA 내부 API가 더 적합한 사이트는 현재 일반 XPath 클릭형 설정만으로는 한계가 있어 후속 소스코드 보완 후보로 남겼다.
- EFRAG처럼 쿠키/동의 레이어가 클릭을 가로막는 사이트는 설정 한계와 공통 click/href 처리 보완 필요성을 notes에 남겼다.
- 중국 재정부처럼 괄호형 전역 XPath가 브라우저에서는 매칭되지만 현재 loop 일반화와 충돌하는 사이트는 공통 workflow 개선 후보로 남겼다.
