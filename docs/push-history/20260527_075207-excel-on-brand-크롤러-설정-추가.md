# Excel ON/Brand 크롤러 설정 추가

- 작성 시각: 2026-05-27 07:52:07
- 브랜치: dev/crawler-current

## 목적

모니터링 사이트 엑셀 파일의 `ON` 및 `Brand` 시트에 있는 수집 대상을 크롤러 workflow 설정으로 변환하여, 오케스트레이션 페이지에서 키워드 필터 기반 모니터링 작업으로 실행할 수 있게 했다.

## 변경이 필요했던 이유

사용자는 제공된 모니터링 사이트 엑셀 파일을 기준으로 크롤러 설정을 만들되, 소스코드는 변경하지 말라고 요청했다. 이 제품에서 `search_terms`는 검색 키워드가 아니라 URL/page 파라미터로 사용되는 구조이므로, 엑셀의 키워드를 `search_terms`에 넣으면 시작 URL 동작이 바뀔 수 있다. 따라서 엑셀 키워드는 수집 후 필터링에 쓰이도록 `filter_terms`에 저장했다.

## 변경 내용

- 엑셀 `ON` 시트 기준 workflow 설정 29개를 추가/보완했다.
- 엑셀 `Brand` 시트 기준 workflow 설정 7개를 추가/보완했다.
- 이 push-history 기록을 추가했다.
- Python, frontend, scheduler, template, test, runtime source 파일은 수정하지 않았다.

## 설계 판단

생성된 설정은 `search_terms: []`를 유지하고, 엑셀 키워드는 `filter_terms`에 넣는 방식을 사용했다. 각 사이트는 확인 가능한 범위에서 법률, 뉴스, 보도자료, 공지, 출판물, 게시판 성격의 모니터링 URL을 선택했다. 안정적으로 반복되는 목록 링크 2개를 추론할 수 있는 경우에는 validator와 현재 loop 일반화 방식에 맞는 `xpath` / `xpath_2` 쌍을 사용했다. 반복 링크 쌍을 안전하게 추론하기 어려운 경우에는 단일 선택 링크 또는 페이지 본문 필터링 방식으로 남기고, 해당 제한사항을 `notes`에 기록했다.

## 검토했거나 보류한 대안

- 키워드를 `search_terms`에 넣는 방식은 사용하지 않았다. 이 값은 현재 제품에서 URL/page 파라미터로 쓰이므로 사용자 요청과 제품 구조에 맞지 않는다.
- 사이트별 parser를 새로 추가하는 방식은 이번 범위에서 보류했다. 사용자가 명시적으로 소스코드 변경 없는 설정 작업을 요청했기 때문이다.
- 이 커밋에서 모니터링을 켜거나 scheduler를 변경하지 않았다. 이번 커밋은 설정 배포만 다루며, 실제 scheduler 변경과 output 관찰은 별도 운영 단계로 남겼다.

- 엑셀 `ON` 및 `Brand` 시트 총 36개 행을 파싱했다.
- 생성/보완된 수집 대상 설정 36개에 대해 `load_workflow_config` + `validate_workflow_config`를 실행했고 모두 통과했다.
- `python -m compileall -q crawler_app crawlers tests`를 실행했고 통과했다.

## 남은 리스크

- 일부 사이트는 가져온 HTML에서 안정적인 반복 기사 목록 XPath를 확인하기 어려워 페이지 본문 fallback을 사용했다.
- RMI old URL은 정적 확인 중 TLS hostname mismatch가 있었다.
- EUR-Lex 페이지는 정적 fetch에서 202 또는 빈 문서를 반환했다.
- Congress와 Consilium은 정적 fetch에서 403을 반환했다.
- Facebook은 400을 반환했다. YouTube, Instagram, Facebook, X는 안정적인 모니터링을 위해 로그인, JavaScript-heavy flow, 채널별 URL, 또는 공식 API가 필요할 수 있다.
- 일부 절대 XPath는 사이트 DOM이 바뀌면 브라우저 DevTools 기준으로 재확인이 필요하다.

## 누적 프롬프트 / 요청 흐름

- 사용자는 먼저 실시간 모니터링 시나리오 테스트를 요청했고, 이후 작업을 일시 중단했다가 다시 전체 진행을 승인했다.
- 이후 사용자는 현재 모니터링을 중지하고, hgz 저장소에서 제품을 갱신한 뒤, `attach`의 엑셀 파일을 읽어 `ON` 및 `Brand` 기준 크롤러 설정을 만들라고 요청했다.
- 핵심 제약은 소스코드 변경 금지, 키워드를 `search_terms`에 넣지 않기, 키워드 필터링이 가능한 기사/보도자료/공지/게시판/법률/출판물 페이지 우선 선택, XPath 한계 보고였다.
- 이 커밋은 생성/보완된 설정 파일과 push-history 기록만 배포한다.

## 누적 프롬프트 / 변경 흐름 추가 기록 - 2026-05-27 18:43:44 +09:00

### 요청 작업 또는 사이트/슬라이스

- 1차적으로 모든 수집 대상 크롤러 설정 완료.

이번 push record에는 별도 프롬프트 전문을 포함하지 않는다. 이번 작업은 수집 대상 설정을 1차 완성 상태로 정리하고, 현재 설정만으로 한계가 있는 사이트들의 후속 검토 상태를 남기는 목적이다.

### 변경 파일

- `attach/모니터링 사이트 및 키워드.xlsx`
- `configs/<수집대상명>.json` 형식의 신규 수집 대상 설정 파일들
- `configs/산업부_입법예고.json`
- `docs/push-history/20260527_075207-excel-on-brand-크롤러-설정-추가.md`

### 변경 이유

전체 수집 대상 목록을 오케스트레이션에서 선택 가능한 크롤러 설정으로 1차 반영하기 위해 설정 파일들을 보완했다. 사이트별로 시작 URL, 페이지 파라미터, 반복 가능한 `open_detail` XPath, 제목/본문 추출 XPath, output 경로, 특이사항을 정리했다.

기존 소스코드 변경 없이 설정만으로 가능한 사이트는 설정값을 맞추고, 설정만으로 안정 수집이 어려운 사이트는 notes에 제한사항을 기록했다. 이 구분은 이후 개발자가 "설정 보정으로 해결할 사이트"와 "공통 workflow 또는 parser 보완이 필요한 사이트"를 빠르게 나누어 판단할 수 있게 하기 위한 것이다.

### 설계 메모와 절충점

- `search_terms`는 기존 제품 계약대로 검색 키워드가 아니라 URL/page 파라미터로 사용한다.
- Excel 또는 사용자 지정 키워드는 가능하면 `filter_terms`에 유지한다.
- 설정만으로 반복 수집이 가능한 사이트는 `xpath` / `xpath_2`를 크롤러 loop 일반화 방식에 맞춰 조정했다.
- ISO, S-OIL, kormany.hu처럼 JSON/API 또는 SPA 내부 API가 더 적합한 사이트는 현재 일반 XPath 클릭형 설정만으로는 한계가 있어 후속 소스코드 보완 후보로 남겼다.
- EFRAG처럼 쿠키/동의 레이어가 클릭을 가로막는 사이트는 설정 한계와 공통 click/href 처리 보완 필요성을 notes에 남겼다.
- 중국 재정부처럼 괄호형 전역 XPath가 브라우저에서는 매칭되지만 현재 loop 일반화와 충돌하는 사이트는 공통 workflow 개선 후보로 남겼다.

### 남은 리스크

- 일부 사이트는 설정만으로는 실제 수집이 불안정하거나 불가능할 수 있다.
- 쿠키/동의 레이어, SPA/API 기반 목록, WordPress JSON API, Cloudflare/차단 페이지, 괄호형 전역 XPath loop 등은 후속 공통 소스코드 보완 검토가 필요하다.

## 누적 프롬프트 / 변경 흐름 추가 기록 - 2026-05-28

### 요청 작업 또는 사이트/슬라이스

- 최신 push-history 항목에 영어 표현이 남아 있어 한글 중심으로 다시 정리한다.
- 최근 다운로드한 설정 파일명이 모두 `excel_`로 시작하므로, 현재 설정의 `name` 값을 기준으로 사람이 알아볼 수 있는 `<이름>.json` 형식으로 변경한다.
- 예시 기준: `유튜브.json`, `경쟁사(S-OIL).json`.
- 이번 변경은 `$git-push-change-log` 흐름으로 커밋 및 push한다.

### 변경 파일

- `docs/push-history/20260527_075207-excel-on-brand-크롤러-설정-추가.md`
- `configs/excel_on_*.json` 29개를 각 설정의 `name` 값 기반 파일명으로 이름 변경
- `configs/excel_brand_*.json` 7개를 각 설정의 `name` 값 기반 파일명으로 이름 변경

### 변경 이유

`excel_on_01.json`, `excel_brand_01.json`처럼 임시 생성 순번이 남아 있으면 운영자가 크롤링 설정 목록을 파일 단위로 확인할 때 대상 사이트를 바로 구분하기 어렵다. 따라서 설정 파일명도 UI에 표시되는 `name`과 맞춰 사람이 직접 읽고 찾기 쉬운 구조로 바꿨다.

push-history도 개발팀과 사용자가 확인하는 기록물이므로, 영어 중심 문구를 한글 중심으로 정리하여 이전 변경의 의도, 검증, 리스크를 바로 이해할 수 있게 했다.

### 설계 메모와 절충점

- 설정 JSON 내부의 `name` 값은 변경하지 않고 파일명만 변경했다.
- 기존 소스코드, 크롤러 실행 흐름, 스케줄러, UI 로직은 수정하지 않았다.
- 파일명에 Windows 금지 문자가 있는지 먼저 확인했고, 충돌되는 대상 파일명은 없었다.
- `configs/유튜브.json`은 rename 전부터 `updated_at` 변경이 작업트리에 있었으며, 해당 내용은 보존했다.
- 영어 자체가 고유명 또는 사이트명인 `EFRAG`, `ISO`, `automotive news`, `electrive`, `Driving Mobility for Europe`, `International Council on Clean Transportation` 등은 현재 설정의 `name` 값을 그대로 파일명으로 사용했다.
