# 오케스트레이션 기능 테스트

## 1. 테스트 목적

크롤링 오케스트레이션 기능이 실제 운영 흐름에 맞게 동작하는지 확인한다.

검증 범위는 다음과 같다.

- 설정 저장은 설정만 저장하는지
- 모니터링 시작 시 Windows Task Scheduler가 정상 생성되는지
- 모니터링 종료 시 Scheduler가 실제로 중단 또는 삭제되는지
- 페이지를 닫아도 Scheduler가 독립적으로 실행되는지
- 수동 실행과 예약 실행이 동일한 크롤링 프로세스를 사용하는지
- 중복 진단, skip, duplicate stop이 정상 동작하는지
- 키워드 발견 시 메일 발송이 정상 동작하는지
- 실패 시 확인 가능한 로그가 남는지
- UI에서 운영자가 상태를 확인할 수 있는지

## 2. 테스트 환경
대상 항목:

- 시그널
- 마켓인사이트
- 다음
- 인베스트조선
- 연합뉴스
- 네이버뉴스
- 구글
- 산업부_보도자료
- 기후에너지부_보도자료

## 3. 버튼별 동작 테스트

| 항목 | 기대 동작 | 테스트 결과 | 비고 |
|---|---|---|---|
| 설정 저장 | settings.json만 저장하고 Scheduler는 건드리지 않음 | 통과 | 설정 저장 전후 Scheduler 목록 비교 |
| 수동 실행 | 선택 항목을 즉시 1회 실행, Scheduler 변경 없음 | 통과 | 수동 실행 후 outputs, history 확인 |
| 모니터링 시작 | 저장된 설정 기준으로 Scheduler 생성/재생성 | 통과 | Task Scheduler에 항목별 task 생성 확인 |
| 모니터링 종료 | 저장된 설정은 유지하고 Scheduler만 종료/삭제 | 통과 | 종료 후 다음 주기에 실행되지 않는지 확인 |
| 재시작 | 종료 후 다시 모니터링 시작 시 기존 설정으로 재등록 | 통과 | settings 유지 여부 확인 |

## 4. 스케줄러 테스트

| 항목 | 기대 동작 | 테스트 결과 | 증거 |
|---|---|---|---|
| 항목별 Scheduler 생성 | 선택된 config마다 개별 task 생성 | 통과 | 등록된 스케줄 화면 / Task Scheduler |
| Cron 반영 | 각 항목의 cron 설정대로 등록 | 통과 | UI 표시값, scheduler registry |
| 페이지 독립 실행 | 웹 페이지를 닫아도 Scheduler 실행 | 통과 | 예약 시간 도래 후 history 확인 |
| 기존 Scheduler 정리 | 모니터링 시작 시 기존 managed task 정리 후 재생성 | 통과 | task 개수 변화 |
| 모니터링 종료 | managed task만 중지/삭제 | 통과 | 다른 task 영향 없음 |
| Last Run 표시 | 미실행 sentinel 시간은 - 표시 | 통과 | UI 화면 |
| Last Result 표시 | raw code 대신 성공/실패 표시 | 통과 | UI 화면 |
