# dev/crawl-20260624 크롤러 API/Tran 통합 반영

## 목적

`crawler-tran-flat-test` 워크스페이스에서 검증한 크롤러 코드와 설정을 `hgz-902/test_crawl` 저장소의 `dev/crawl-20260624` 브랜치로 공유한다.

이번 push는 테스트 산출물이나 로컬 런타임 상태가 아니라, 개발팀 검토와 다른 환경 재현에 필요한 소스코드, 크롤러 설정, 템플릿, 정적 파일, 테스트, 스크립트, 문서만 포함한다.

## 포함한 주요 변경

- 크롤러 설정 파일 최신화
  - `configs/*.json`에 현재 테스트 워크스페이스 기준의 수집처 설정을 반영했다.
  - 검색어/필터어 설정이 남아 있는 설정은 그대로 보존했다.
  - `.env`, `outputs`, `runtime`, `logs`, `orchestration_state`, `.venv`는 push 대상에서 제외했다.

- Parquet flat 변환 구조
  - `filter` 산출물을 `tran` 하위 폴더 없이 `tran/*.parquet`로 평탄하게 생성하도록 변경한 코드가 포함된다.
  - `download_YYYYMMDD_HHMISSffffff.parquet`, `text_YYYYMMDD_HHMISSffffff.parquet`, `metadata_YYYYMMDD_HHMISSffffff.parquet` 형식을 사용한다.
  - `metadata_*.parquet`에는 원본 `workflow_records.json` bytes와 parquet 변환 파일 매핑 manifest를 함께 보존한다.

- Parquet 전환 UI/API
  - 상단 메뉴에 Parquet 전환 화면을 추가했다.
  - `outputs/*/tran/*.parquet` 목록을 표시하고, 단일 전환 다운로드와 선택 ZIP 다운로드를 지원한다.
  - 다운로드는 `filter` 원본 파일을 내려주는 것이 아니라 parquet 내부의 `content_bytes`를 다시 원본 파일로 복원해 반환한다.
  - metadata parquet 전환 시 매핑 정보를 제거하지 않고 보존한다.

- 뉴스 검토 UI 백엔드 이관
  - Databricks 의존 API를 로컬 SQLite 기반으로 사용할 수 있도록 `news_ui_api`, `news_sqlite_store`, `news_ingestion`, `news_grouping`, `news_sentiment` 계층을 추가했다.
  - 구현 대상 API는 `/api/news`, `/api/news/grouped`, `/api/filter-options`, `/api/stats`, `/api/news/{article_id}/read`, `/api/news/{article_id}/favorite`, 분석 저장/조회 API다.
  - `POST /api/news/{article_id}/analyze`의 OpenAI 직접 호출은 제거했고, 내부 모델/외부 분석 결과를 저장 API로 받는 구조를 남겼다.
  - 기본 그룹핑은 제목 기반이며, 운영 기본값은 실험 결과 기준 C05 계열 설정을 사용하도록 정리했다.

- 중복 진단 기록 개선
  - `workflow_records.json`의 `search_term`, `filter_term`을 항상 배열로 저장한다.
  - 같은 기사 URL 또는 parser duplicate key가 여러 검색어/필터어에서 발견되면 새 record를 중복 저장하지 않고 대표 record의 배열에 병합한다.
  - `latest.json`은 내부 중복 경계 파일이라 기존 문자열 기반 동작을 유지하되, 배열 record도 안전하게 처리하도록 보완했다.

- 오케스트레이션/스케줄러 및 실행 보조
  - `crawler_app/orchestration.py`, `scheduled_runner.py`, `windows_scheduler.py` 등 오케스트레이션 실행/상태 관리 코드를 포함한다.
  - 다만 실제 로컬 상태 파일인 `orchestration_state`는 운영 환경별 상태이므로 커밋하지 않았다.

## 설계 판단

- 원본 산출물과 runtime 상태를 함께 올리면 Git 저장소가 무거워지고, 다른 환경에서 오래된 실행 상태가 섞일 수 있어 제외했다.
- Parquet 전환은 원본 `filter` 파일을 다시 찾는 방식이 아니라 parquet 내부 bytes를 기준으로 복원한다. 원본 파일이 삭제된 뒤에도 parquet만 있으면 복원 가능해야 하기 때문이다.
- 뉴스 검토 API는 당장 로컬/Windows 서버에서 사용할 수 있도록 SQLite를 기본 저장소로 뒀다. PostgreSQL이나 Databricks는 성능/운영 요건이 확정된 뒤 교체할 수 있다.
- 그룹핑은 API 호출 시 실시간 계산하지 않고 적재/동기화 단계에서 미리 계산하는 구조를 유지한다. 개발팀이 API 응답 지연을 우려했기 때문이다.

## 제외한 항목

- `.venv`: 재생성 가능한 가상환경이다.
- `outputs`: 크롤링 산출물이다.
- `runtime`: SQLite DB, 로컬 실행 상태, 테스트 중 생성되는 파일이다.
- `logs`: 로컬 실행 로그다.
- `orchestration_state`: 사용자/서버별 모니터링 상태 파일이다.
- `memory`, `imsi`, `qa-artifacts`: 세션 기록/임시 검증 산출물이다.
- `.env`, 쿠키, 토큰, 비밀번호: 민감정보라 포함하지 않았다.

## 다른 환경에서 필요한 준비

1. Python 가상환경 생성
   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r .\requirements.txt
   ```

2. 서버 실행
   ```powershell
   python -m uvicorn crawler_app.web:app --host 127.0.0.1 --port 3010
   ```

3. 뉴스 UI API용 DB는 `runtime/news_ui/news_ui.sqlite3`에 생성된다. 다른 환경에서는 수집 후 ingestion/sync가 실행되어야 `/api/news`, `/api/news/grouped`, `/api/filter-options` 결과가 채워진다.

4. Naver/Daum/OpenAI 등 외부 키가 필요한 기능은 로컬 `.env`에 키를 넣어야 한다. `.env`는 커밋하지 않는다.

## 남은 리스크

- `hgz-902/test_crawl`의 기존 `main`과 파일 구성이 크게 달라 삭제/추가 diff가 크다. 이번 브랜치는 `crawler-tran-flat-test` 현재 상태를 기준으로 통합 반영하기 위한 별도 dev 브랜치다.
- 실제 운영 서버에서는 `.env`, proxy 파일, 오케스트레이션 상태, SQLite DB 생성 위치를 서버 정책에 맞게 별도 구성해야 한다.
- 그룹핑 품질은 제목 기반 유사도와 threshold에 영향을 받으므로, 운영 데이터가 늘면 추가 샘플 검수가 필요하다.
